# 界面设计约定

## 已批准的方向

- **产品**：为 Windows 服务器维护者呈现硬件状态、历史趋势和网络流量。
- **性格**：精确、克制、便于长时间观察。
- **场景**：精密仪表台；灰白与石墨色中性色阶承载面板和文字。
- **视觉重点**：CPU 使用率为主趋势，桌面跨两行；内存使用率和 CPU 温度为辅助趋势，颜色服务于真实数据。
- **识别细节**：实时通道状态标记只传达真实状态，不作为装饰。

界面保留亮色、暗色和跟随系统三种主题，保持安静的导航与控件（quiet chrome），用有边界的面板组织信息；手机上按阅读顺序堆叠，不通过缩小字体换取空间。

## 轻量审视

审视结合源码、已有测试和实际页面截图进行；功能源码检查与浏览器视觉检查分别验证，不能互相替代。

- 原有 `styles.css` 和 `styles/observatory.css` 存在大范围叠加、后置覆盖，主题与页面规则归属不清，增加维护和回归判断成本。
- 原有样式存在多处渐变、装饰效果及过小字号，视觉重点容易从测量值转向界面外壳。
- 旧的 Paper 专用源码测试绑定了具体片段和曾经的移动排列；应转为检查当前的共享面板、内容与响应式契约，不把源码匹配当作实际渲染证明。

## 九轮设计摘要

1. **间距**：建立一致的面板、控件和分组节奏；紧凑屏幕降低留白但保留可触控空间。
2. **颜色**：以中性灰白和石墨为基底，语义色及数据色仅用于状态和测量值；避免渐变、发光和有色阴影。
3. **图标**：沿用项目的共享线性图标，删除不承载意义的装饰，不引入图标依赖。
4. **文案**：用简短、具体的标签说明当前数据、范围与状态，不虚构结果或功能。
5. **字体**：使用有限的字号与字重，正文及辅助文字不小于 12px；数值采用等宽数字以便比较。
6. **布局**：保留首页、网络、设置三个入口；首页按概览页头、核心指标、趋势、进程、存储的顺序组织；开机时间和运行时间融入概览页头，不再单独展示状态栏。CPU 频率、温度和功耗并入六项核心指标，桌面两行三列、手机三行两列，窄屏顺序可读；数据过期和时间异常仍通过异常提示展示。
7. **细节**：共享面板使用清晰边界，交互控件保留可见焦点；趋势区突出 CPU，辅助图保持独立且易读。
8. **视觉内容**：图表使用真实采样及其缺失区间，不增加装饰性图像或伪造数据。
9. **动效**：只保留有意义的轻量反馈，避免持续装饰动画和宽高等布局属性动画，并尊重减少动态效果设置。

## 样式分层

入口 `src/main.ts` 按以下顺序加载样式：

1. `src/styles.css`：主题变量、基础元素、共享卡片与可访问性规则。
2. `src/styles/observatory.css`：应用外壳、导航及首页仪表台布局。
3. `src/styles/network.css`：网络页面、排行和应用详情。
4. `src/styles/settings.css`：设置页面。

共享 `.card` 定义基础边框、表面和圆角。页面样式承载各自的布局与状态；维护时应复用共享规则，避免再建立相互覆盖的全局主题层。网络和设置的主面板直接复用 `.card`，不重复声明相同的基础表面规则。

## 功能边界与验证

本轮不新增依赖，也不改变路由或 API 行为。保留实时连接与重试、跟随系统/亮色/暗色主题、网络筛选与排行、应用详情模态框及焦点返回、设置草稿与保存，以及真实遥测的未知值、过期、缺样和错误状态。视觉调整不能将缺失数据表示为零，也不能遮蔽必要操作或改变统计口径。

Node 测试包含数据行为和源码结构检查；后者只能发现部分静态回归，不能替代亮暗主题、响应式布局、键盘焦点和模态框的浏览器实测。

2026-11-06 验证：45 项前端测试、类型检查和生产构建通过。实际页面检查覆盖 1440px 首页／网络页、1024px 设置页及 390px 手机布局，包含浅色、深色和跟随系统；实测了时间预设、范围切换保留预设、手机筛选展开、明细完整时间与未统计方向、Escape 关闭和焦点返回。未在生产后端执行设置保存、忽略或恢复，也未进行生产部署。
