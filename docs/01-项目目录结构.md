# 项目目录结构

## 原始需求
  - 1：win11系统
  - 2：实现语言和框架不限（但是尽量追求高效）
  - 3：收集电脑上的硬件实时信息，包括不限于（cpu、内存、硬盘温度，cpu占用率，内存占用率，开机时间，cpu频率）
  - 4：收集电脑上的网络使用量信息，要求能按照app统计，能区分wan和lan的流量，能自定义时间间隔
  - 5：收集到上述信息后，在本地开启http服务，端口自定义，能在在web页面上看到上述信息
  - 6：页面要求美观，可定制，但可以后续微调，优先实现功能
  - 7：硬件信息采集可以使用LibreHardwareMonitor，网络信息采集需要你帮我选型
  - 针对以上需求，请给出你推荐的框架和方案

## 目录说明

### docs/
存放设计说明、开发计划、接口草案、部署说明等文档。当前先放四份核心方案文档。

### src/Monitor.Service/
作为后台主进程：
- 托管采集任务
- 管理配置加载
- 启动 Web API
- 启动 SignalR 推送
- 注册 Windows Service 生命周期

### src/Monitor.Hardware/
负责硬件信息采集：
- CPU 温度
- CPU 频率
- CPU 占用率
- 内存总量/使用量
- 磁盘温度
- 开机时间

### src/Monitor.Network/
负责网络统计：
- 按应用聚合流量
- 区分上传/下载
- 区分 WAN / LAN
- 提供自定义时间粒度的统计结果
- 可扩展到连接明细或会话分析

### src/Monitor.Storage/
负责数据存储：
- SQLite 建表与迁移
- 实时缓存落盘
- 聚合查询
- 历史清理策略

### src/Monitor.Contracts/
放公共定义：
- DTO
- Query Model
- 配置对象
- 枚举（流量方向、地址分类、传输协议等）

### src/Monitor.WebApi/
提供：
- REST API
- SignalR Hub
- 静态文件服务
- 前端托管

### src/Monitor.Frontend/
前端页面：
- 总览页
- 硬件实时页
- 网络统计页
- 应用排行页
- 设置页
